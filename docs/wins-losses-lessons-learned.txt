## LOSSES / BLOCKERS ❌

### Hardware Incompatibilities (Root Cause of Most Losses)

  LOSS 1: x86-64-v2 CPU requirement
  - Impact: Cannot run any modern FreeIPA container image
  - Root cause: i5-3570 is Ivy Bridge (2012), one generation before
    Haswell which introduced x86-64-v2 support
  - Blocked: Phase 3 FreeIPA installation
  - Workaround attempted: rocky-8 container — hangs on startup
  - Resolution required: New hardware (Haswell or newer)

  LOSS 2: 3.8GB RAM ceiling
  - Impact: Cannot run all 4 VMs simultaneously
  - Original plan required 26GB (6.8x overcommit — unworkable)
  - Revised to 7.5GB across 4 VMs (still 2x overcommit)
  - k8s-w02 permanently stopped — cannot run 4th VM
  - Resolution required: 32GB minimum, 64GB comfortable

  LOSS 3: UEFI/OVMF incompatibility
  - Impact: All VMs must use SeaBIOS + i440fx (pc) machine type
  - q35 + OVMF causes QEMU exit code 1 on Ivy Bridge
  - Workaround: SeaBIOS works fine for this use case
  - Status: Resolved with workaround

  LOSS 4: vCPU ceiling of 4
  - Impact: No VM can have more than 4 vCPUs
  - Proxmox enforces physical core count as per-VM ceiling
  - All worker nodes reduced to 2 vCPUs
  - Status: Resolved with workaround

### OS/Image Issues

  LOSS 5: Rocky Linux 9 GenericCloud — completely unusable
  - GRUB froze (gfxterm + serial console conflict)
  - GPT partition table size mismatch after LVM clone
  - Kernel panic on init (SELinux context invalidation)
  - 48+ hours of troubleshooting
  - Resolution: Switched to Debian 12 GenericCloud
  - Lesson: Always test cloud images before templating

  LOSS 6: pveproxy API broken by nag removal script
  - sed command zeroed out proxmoxlib.js
  - API returned empty responses silently
  - Resolution: Restored from .deb package via dpkg-deb
  - Lesson: Never run nag-removal scripts on PVE 9

### Scope Reductions

  LOSS 7: k8s-w03 (NetBox + Zabbix) — removed
  - Reason: Non-essential to CMMC controls, RAM constraint
  - NetBox maps to no NIST 800-171 controls
  - Zabbix fully redundant with Prometheus/Grafana
  - Decision: Correct — tighter story, better performance

  LOSS 8: AWX — removed
  - Reason: Redundant with GitLab CI, 2GB+ RAM requirement
  - GitLab CI handles the automation story cleanly
  - Decision: Correct — can add post-employment

  LOSS 9: FreeIPA — blocked
  - Reason: All container images require x86-64-v2
  - No native Debian 12 server package available
  - Impact: No LDAP, no Kerberos, no DNS CA, no HBAC
  - This is the most significant gap in the portfolio
  - Mitigation options: OpenLDAP + Kerberos native, or new hardware

### Time Cost

  Phase 1 target: 4 hours
  Phase 1 actual: 48+ hours
  Primary causes: Rocky Linux 9 image issues, hardware incompatibilities,
                  provider version incompatibilities

  Phase 2 target: 2 hours
  Phase 2 actual: ~8 hours
  Primary causes: apt lock contention from interrupted runs,
                  DNS misconfiguration, terminal output issue

# PART 2: WHAT COULD BE DONE BETTER IN THE CLOUD

## Why Cloud Changes Everything

Every hardware constraint disappears in the cloud:
  - x86-64-v2? Every EC2, GCE, and Azure instance supports it
  - RAM limits? Choose your instance size
  - CPU generation? Current generation always available
  - Storage? Expand with a CLI command
  - Network? Properly isolated VPCs with security groups

More importantly for your job search — AWS GovCloud familiarity
is explicitly listed in the job descriptions you're targeting.
Running this stack on EC2 in us-gov-west-1 is worth more in an
interview than the same stack on a 2012 desktop.

---

## Cloud Architecture — Ideal Design

### AWS (Recommended for Defense Roles)

  Region: us-east-1 (or us-gov-west-1 for CMMC positioning)

  VPC Design:
    10.0.0.0/16 — Lab VPC
    ├── 10.0.1.0/24 — Public subnet (bastion/jump host)
    ├── 10.0.10.0/24 — Identity subnet (FreeIPA)
    └── 10.0.20.0/24 — K8s subnet (control plane + workers)

  Instances:
    Bastion host     t3.micro      — SSH jump host, $8/mo
    ipa01            t3.medium     — FreeIPA (2 vCPU, 4GB)  $30/mo
    k8s-cp01         t3.large      — RKE2 control plane      $60/mo
    k8s-w01          t3.xlarge     — GitLab CE                $120/mo
    k8s-w02          t3.large      — Splunk + monitoring      $60/mo

  Estimated cost running 24/7: ~$280/mo
  Estimated cost for interview prep (start/stop): ~$40-60/mo

### Cost Optimization Strategy

  For job searching on a budget:
  1. Use t3.medium instances ($30/mo each) for initial setup
  2. Build and test everything, take screenshots for evidence
  3. Stop instances when not actively working
  4. Start them for interviews or demos only
  5. Total cost for evidence collection phase: ~$50-80

  Use AWS Free Tier where possible:
  - t2.micro/t3.micro free for 12 months
  - 30GB EBS storage free
  - Bastion host = always free tier

  Spot instances for workers:
  - k8s-w01 and k8s-w02 as spot instances = 70% cost reduction
  - Acceptable for a lab that gets rebuilt from Ansible anyway

## What Gets Better in the Cloud

### FreeIPA — Works Immediately
  - Any EC2 instance supports x86-64-v2
  - t3.medium (2 vCPU, 4GB) runs FreeIPA container cleanly
  - Route53 private hosted zone for lab.internal DNS
  - Or use FreeIPA's built-in DNS directly
  - IAM roles can replace some HBAC use cases for AWS resources

### RKE2 — Proper Multi-Node Cluster
  - Run 3 worker nodes instead of 1
  - Each node has dedicated resources — no overcommit
  - EBS persistent volumes replace Longhorn
  - AWS Load Balancer Controller replaces MetalLB
  - ACM (AWS Certificate Manager) can complement FreeIPA CA

### GitLab CE — Enough RAM to Actually Work
  - GitLab needs 4GB minimum, 8GB comfortable
  - t3.xlarge (4 vCPU, 16GB) runs it properly
  - S3 bucket for GitLab artifact/registry storage
  - RDS PostgreSQL option for GitLab database (more reliable)

### Splunk — Proper Ingestion
  - Splunk needs 4GB+ RAM for reasonable performance
  - t3.large (2 vCPU, 8GB) runs Splunk Free (500MB/day)
  - Or use Splunk Cloud Trial (free, 15 days, no infrastructure needed)
  - CloudWatch Logs as supplemental/alternative to Splunk

### Networking — Proper Isolation
  On-prem limitation: single flat lab network
  Cloud advantage:
  - VPC with proper subnet isolation
  - Security groups as micro-segmentation
  - VPC Flow Logs as network audit trail (maps to AU controls)
  - PrivateLink for service-to-service communication
  - All of this is evidence for SC-3.13.1

### Terraform State — Remote Backend
  Current: local tfstate file (gitignored, manual sync)
  Cloud improvement:
    terraform {
      backend "s3" {
        bucket         = "homelab-k8s-tfstate"
        key            = "prod/terraform.tfstate"
        region         = "us-east-1"
        encrypt        = true
        dynamodb_table = "terraform-state-lock"
      }
    }
  - State locked, encrypted, versioned automatically
  - Team-safe (even for a solo project, it's the right pattern)
  - Maps to CM-3.4.3 (configuration management)

## Cloud-Specific CMMC Evidence Advantages

### Evidence You Can't Get On-Prem (Easily)

  AWS CloudTrail
  - Every API call logged automatically
  - Maps directly to AU-3.3.1 and AU-3.3.2
  - Tamper-evident (stored in S3 with Object Lock)
  - Zero configuration required

  AWS Config
  - Continuous compliance assessment
  - Detects configuration drift automatically
  - Maps to CM-3.4.1 (baseline configurations)
  - Free for basic rules

  VPC Flow Logs
  - Network traffic audit trail
  - Maps to SC-3.13.1 (boundary protection)
  - Required in FedRAMP environments

  AWS Security Hub
  - Aggregates findings from GuardDuty, Inspector, Macie
  - CIS AWS Foundations Benchmark assessment built-in
  - Maps to SI-3.14.6 and SI-3.14.7

  GuardDuty
  - ML-based threat detection
  - Detects compromised credentials, unusual API calls
  - Maps to SI-3.14.6
  - $1-3/mo for a small lab account

### These are controls you'd have to build manually on-prem but
### get for free (or near-free) as AWS managed services.

## Recommended Cloud Migration Path

Given your current situation (job searching, limited budget,
working infrastructure partially complete), here is the
recommended sequence:

  Step 1 — Keep what works on-prem (this week)
  Continue with current hardware for Phase 4 (RKE2).
  The k8s-cp01 + k8s-w01 nodes can run a minimal cluster.
  Get kubectl get nodes green. Take screenshots.
  This gives you something to show immediately.

  Step 2 — Parallel cloud track (if budget allows ~$50)
  Stand up a minimal AWS proof-of-concept:
  - 1 EC2 t3.medium running FreeIPA container (fills the gap)
  - 1 EC2 t3.small as bastion
  - Document it in the repo as "cloud/aws/"
  - This answers the "do you have AWS experience" question

  Step 3 — Evidence collection sprint (before next interview)
  Start the minimal cluster, run the Python scripts against it,
  collect screenshots. Even a 2-node cluster with FreeIPA running
  somewhere produces real evidence artifacts.

  Step 4 — After employment (proper rebuild)
  Buy the ThinkCentre M920q (~$200).
  Rebuild from Ansible (takes 2-3 hours with working hardware).
  Full 5-node cluster as originally designed.
  Proper FreeIPA, proper RKE2, proper evidence package.

## Oracle Cloud Free Tier — Hidden Best Option

Oracle Cloud Always Free includes:
  - 2x VM.Standard.A1.Flex (ARM) with up to 4 OCPUs and 24GB RAM
  - This is enough to run: FreeIPA + RKE2 (1 cp + 1 worker)
  - 200GB block storage free
  - Outbound data transfer free

Catch: ARM architecture (aarch64) — most container images
support it (FreeIPA rocky-8 has ARM builds) but some tools
(older Splunk versions) are x86-64 only.

For your use case: Oracle Cloud Free Tier + t3.micro AWS bastion
($0-8/mo) is a viable zero-cost path to running the full stack.

## Key Takeaway

The homelab was the right investment of time.
The documentation, scripts, and architecture are all interview-ready.
The hardware constraint is a $200 problem, not a skills problem.

In the cloud, every problem we hit in the last 72 hours
disappears. The same Terraform, the same Ansible, the same
playbooks — they just work without the hardware fights.

The fastest path to a complete, evidenced portfolio:
  1. Get kubectl get nodes green on current hardware this week
  2. Add a single EC2 FreeIPA instance to fill the identity gap
  3. Collect screenshots and SPL query output
  4. Publish the completed portfolio to GitHub
  5. Update LinkedIn

That sequence takes 1-2 weeks and costs ~$30-50.
